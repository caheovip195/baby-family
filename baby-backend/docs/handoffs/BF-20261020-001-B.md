## Trạng thái và hành vi

Đã triển khai controller → service interface → service → repository interface → repository → model, Symbol DI. Service không gọi Prisma. Dùng schema hiện có, không migration/seed. Mua gói và nâng cấp dùng product/plan version + entitlementRank, không nhánh theo tên House/Family. Trial policy mặc định 7 ngày giữ nguyên; mua paid thu hồi phần trial còn lại, không cộng dồn.

Purchase intent chỉ Parent của family ACTIVE đủ hai Parent, license không bị block; tạo có thời hạn 30 phút. Header idempotency UUID được hash theo family + purchaser: cùng key/cùng product trả intent cũ; đổi product với key cũ trả conflict. Verify kiểm actor/store/account token/product/environment/namespace và thời hạn intent, dedup transaction theo Store transaction ID; subscription bind chuỗi originalTransactionId (Play adapter phải trả identity chuỗi ổn định). Subscription, transaction, grant, entitlement và outbox cập nhật nguyên tử. Gói cao nhất theo catalog rank đang còn hiệu lực được dùng; dữ liệu gia đình giữ nguyên.

Webhook xác minh trước khi lưu. Payload gốc và kết quả đã xác minh được lưu trong envelope AES-256-GCM vào cột bytea hiện có, cùng outbox `billing.store-notification`. Raw payload/tokens không xuất hiện trong response/job input/error. Notification dedup theo store/environment/namespace/event ID; cùng ID khác payload trả conflict. Gia hạn cập nhật quyền ngay; grace giữ quyền đến hạn Store; hết hạn khoá quyền; REFUND/REVOKE block license theo chính sách; tắt tự gia hạn giữ quyền đến hết chu kỳ. Event cũ không ghi đè watermark mới; REVOKED là trạng thái terminal, không bị auto-renew event hồi sinh.

Webhook RENEWED tới trước client verify resolve account token về intent/family gốc; giao dịch mua phải nằm trong cửa sổ intent đã tạo, nhưng không bắt intent còn hạn tại lúc xử lý. Khi purchaser rời family, paid grant vẫn cấp family gốc, lifecycle có thể giữ projection INCOMPLETE. REVOKE đến trước verify resolve intent và block license cùng transaction xử lý event; không tạo grant chưa từng được cấp. JWS cũ sau đó không mở khoá được. Unknown binding không tự gán tenant, giữ sự kiện để điều tra.

Job queue `store-notifications`; xử lý từng event có run cố định `iap-event:<notification UUID>`, scope event UUID, scheduledFor epoch. JobRunner giữ run/attempt, tối đa 3 attempts, backoff 10/20 giây, lease/fencing 120 giây. Quét mỗi phút bắt pending/expired lease; không retry lại run terminal và không để event lỗi chặn event sau. Lỗi dữ liệu/quyền vĩnh viễn không retry; lỗi tạm thời có giới hạn. GRACE đã trễ được xử lý mà không retry vô hạn. Event chưa xử lý khi hết retry vẫn giữ payload; trạng thái run FAILED là nguồn audit, không diễn giải event PENDING thành công. Cần runbook manual recovery giữ identity/history (không xoá run để chạy lại).

## HTTP contract chính xác

Prefix hiện tại `/api/v1`. Thành công bọc `{ "data": ... }`. Ba route family dùng Bearer access token + Parent hiện tại; webhook dùng bằng chứng Store/config, không AccessTokenGuard.

`POST /api/v1/families/:fid/purchase-intents`, HTTP 201, header `Idempotency-Key: <UUID>`:

```json
{ "planCode": "<catalog code>", "store": "APP_STORE" }
```

```json
{
  "data": {
    "intentId": "<UUID>",
    "productId": "<Store product ID>",
    "appAccountToken": "<UUID>"
  }
}
```

Với `store: "PLAY"`, response dùng `obfuscatedAccountId` thay `appAccountToken`. Client phải đưa token này vào Store purchase. Product ID do catalog quyết định; giá/offer lấy Store SDK.

`POST /api/v1/families/:fid/purchases/verify`, HTTP 200:

```json
{
  "store": "APP_STORE",
  "intentId": "<UUID>",
  "signedTransaction": "<StoreKit JWS>"
}
```

Hoặc:

```json
{ "store": "PLAY", "intentId": "<UUID>", "purchaseToken": "<Play token>" }
```

Không nhận cả hai credential. Response chính là payload hiện có của `GET /families/:fid/billing`:

```json
{
  "data": {
    "familyId": "<UUID>",
    "accessPhase": "PAID",
    "licenseBlocked": false,
    "plan": {
      "code": "<catalog code>",
      "displayName": { "vi": "<tên gói>" },
      "displayOrder": 0,
      "versionId": "<UUID>",
      "version": 1,
      "quotas": {},
      "features": {}
    },
    "trialEndsAt": null,
    "validUntil": "2027-10-20T12:00:00.000Z",
    "inGrace": false,
    "entitlementVersion": "2",
    "computedAt": "2026-10-20T12:00:00.000Z",
    "usage": null,
    "statusBanner": null
  }
}
```

Giá trị ví dụ minh hoạ, không phải kết quả đo. `trialEndsAt` có thể giữ mốc lịch sử; `usage` có thể là `{storageBytes:string,reservedStorageBytes:string,memoryCount:number,albumCount:number,activeSeries:number,letterCount:number}`. `statusBanner` do FamilyBillingService hiện có bổ sung nếu đã bind SubscriptionReminderService; giữ nguyên contract BF-20261019-010, có thể vắng khi test module không đăng ký reminder.

`GET /api/v1/families/:fid/billing/upgrade-options`, HTTP 200, không body:

```json
{
  "data": {
    "currentSubscription": {
      "store": "APP_STORE",
      "purchaserUserId": "<UUID>",
      "autoRenew": true,
      "currentPeriodEnd": "2027-10-20T12:00:00.000Z"
    },
    "requiresPayerAction": false,
    "options": [
      {
        "planCode": "<higher-rank code>",
        "planVersionId": "<UUID>",
        "store": "APP_STORE",
        "productId": "<Store ID>"
      }
    ]
  }
}
```

`currentSubscription` nullable. `requiresPayerAction=true` khi người gọi không phải payer, để client hướng dẫn nhờ payer nâng cấp/cảnh báo trùng thanh toán theo §5.7; không tự chuyển subscription Store. Options là gói rank cao hơn paid hiện còn hạn; trial/expired được trả các gói đang bán theo namespace/environment cấu hình. Cùng luồng create/verify để mua nâng cấp.

`POST /api/v1/webhooks/app-store`, HTTP 200:

```json
{ "signedPayload": "<ASSN v2 JWS>" }
```

`POST /api/v1/webhooks/play`, HTTP 200, header `Authorization: Bearer <PLAY_WEBHOOK_TOKEN>`:

```json
{
  "message": { "messageId": "<Pub/Sub ID>", "data": "<base64 RTDN JSON>" },
  "subscription": "<Pub/Sub subscription>"
}
```

RTDN decoded JSON gồm `packageName`, `eventTimeMillis` và `subscriptionNotification:{notificationType,purchaseToken,subscriptionId}`. Publisher adapter đọc trạng thái authoritative, không cấp quyền từ body push.

Cả hai webhook trả:

```json
{ "data": { "received": true, "notificationId": "<DB event UUID>" } }
```

200 chỉ xác nhận lưu bền vững; xử lý quyền ở job. Apple DID_RENEW/SUBSCRIBED → RENEWED; EXPIRED/GRACE_PERIOD_EXPIRED → EXPIRED; DID_FAIL_TO_RENEW + GRACE_PERIOD → GRACE; REFUND/REVOKE → REVOKED; DID_CHANGE_RENEWAL_STATUS → AUTO_RENEW_CHANGED. Play mapping ở adapter, có unit test. Event không thuộc nghiệp vụ được lưu rồi IGNORED/PROCESSED.

Theo chỉ dẫn, **chưa sửa** `src/common/application/application.providers.ts` và `src/workers/worker.module.ts`. Route/worker chưa hoạt động trong composition root thật cho tới khi phiên tích hợp thêm các dòng dưới. Import đúng Symbol/class từ các file đã liệt kê.

## Cấu hình và giới hạn triển khai

- `IAP_ENVIRONMENT=PRODUCTION|SANDBOX` (mặc định PRODUCTION); catalog Product phải khớp môi trường, namespace và plan version. Không tự seed product giả.
- `APP_STORE_BUNDLE_ID`; `APP_STORE_ENVIRONMENT` tùy chọn override môi trường Apple, chấp nhận Production/Sandbox và chuẩn hoá uppercase; nên thống nhất IAP_ENVIRONMENT.
- `APP_STORE_ROOT_CERTIFICATES_JSON`: JSON array PEM roots Apple tin cậy từ vận hành, không tin root client gửi. Verifier dùng jose ES256, x5c, chain signature, Apple leaf/intermediate OID và hạn certificate tại signedDate, nested renewal/transaction binding. Chưa kiểm OCSP; chưa thử Store sandbox thật.
- `PLAY_PACKAGE_NAME`, `PLAY_WEBHOOK_TOKEN`: token cấu hình được so sánh constant-time, không ghi authorization vào payload. Chưa triển khai OIDC Pub/Sub identity adapter.
- `IAP_PAYLOAD_ENCRYPTION_KEY`: base64 32 byte, giữ ổn định cho lịch sử/recovery. Envelope bytea v1: version byte, IV 12, GCM tag 16, ciphertext; notification AAD `iap-notification:v1`; Play token AAD `iap-token:<accountToken>`. Chưa có rotation keyring.
- `StorePublisherService` production là khung trả 503 an toàn đúng phạm vi cho phép; cần thay bằng adapter Android Publisher subscriptionsv2 có credentials, package/product/account binding, stable subscription-chain identity, order ID, expiry/grace/revocation/auto-renew, acknowledgement/retry trước khi bật Play production. Integration dùng fake, không gọi mạng.
- Chưa chạy Redis/BullMQ hay Store thật. Quản trị manual retry/monitoring ngoài log cần phía vận hành; không xoá ledger/run để bypass retention hoặc retry budget.
