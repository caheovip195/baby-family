## Changes API đã thực hiện

- Controller mới `OfflineSyncController`, service interface/implementation và repository interface/implementation, model riêng. GET `/api/v1/families/:familyId/changes?cursor=<opaque>&limit=100`; không có JSON request body. `limit` integer 1..200, mặc định100.
- Hợp đồng success root `{items,nextCursor,hasMore}` qua `@RawResponse()`, không bọc envelope. Memory projection tối thiểu `{id,version}`; app gọi GET detail hiện có để lấy full projection và URL ảnh ký mới. Comment gồm id/memoryId/body/authorUserId/parentCommentId; reaction gồm id/memoryId/userId/type; version chỉ memory. Không trả nội dung tombstone.
- Reaction khóa ghép nên ID đồng bộ là `memoryId:userId`. Cursor chứa receipt UUID riêng, client không sử dụng UUID receipt làm entity ID.
- Dùng raw-managed log mới `app.offline_memory_changes` vì không có lịch sử ID đã gửi từng người xem trong bảng cũ: chỉ đọc updated_at không thể phát tombstone khi thu hồi grant mà không lộ ID private. Log append chỉ lưu identity/op/fingerprint, không lưu body; audit đủ ba cột timestamptz(3), trigger `ops.touch_audit_columns`, index cursor/latest, FK user/family cascade. Prisma khai báo `@@ignore`, theo precedent `UserAssetVariant`; không sinh/sửa generic persistence/service.
- Poll materialize trạng thái hiện tại, so fingerprint với receipt mới nhất, tạo batch log khi thay đổi; những ID trước đây được phép sync nay biến mất khỏi ACL nhận delete. Thu hồi membership trả404, client xoá cache family. Dòng log upsert cũ đang chờ cũng chuyển delete khi quyền hiện tại mất, không trả lại body từ lịch sử.
- ACL dùng helper memoryContentScope/viewerExclusions hiện có; Parent feed statuses (không draft), Circle phải đủ grant của mọi bé liên quan; PRIVATE chỉ chủ; thư chưa mở không trả cho người khác; pending review không trả Circle; hide/report/block áp theo feed/comments. Gate membership/entitlement service hiện có giữ nguyên.
- Log được tạo lúc pull: `updatedAt` là watermark server quan sát, không phải source timestamp/thời gian offline. Nhiều sửa đổi giữa hai pull gộp thành state cuối; mỗi entity có thể có nhiều event qua các poll. Giữ trật tự `(log.updated_at, log.id)` tăng dần, truy vấn `>` cặp khóa. Advisory lock per family/user + batch timestamp > max timestamp đã commit giải quyết cùng millisecond, không dùng offset.
- Initial metadata bootstrap bao phủ **mọi entity hiện được xem kể cả ký ức >90 ngày**; cần vậy để thu hồi cache full feed. Log replay/cursor window90 ngày; empty initial cursor watermark là now. Cursor giữ từ khi chưa có dữ liệu vẫn dùng được. Cursor quá90 ngày →409 yêu cầu clear/full resync.
- Bootstrap changes trước khi full feed; cache cũ chưa từng sync phải clear khi bật giao thức. Không thể bảo đảm tombstone cho ID client đã cache trước lần server lập receipt đầu tiên.

        "id": "<comment UUID>",

## Kết quả và semantics

Dùng lại bảng `ops.idempotency_records`, unique `(scope_key, operation, idempotency_key)`. Thêm service/repository/model viết tay mới. Controller chỉ chuyển actor/input và callback đến service interface; Prisma chỉ ở repository. Không có bảng hoặc job mới.

Các route mới nhận header UUID tùy chọn. Thiếu header: chạy đúng workflow cũ. Header có nhưng không đúng UUID: HTTP 400. Chuẩn hóa UUID về lowercase. Scope = user đã xác minh; ghi chú mẫu public dùng scope `legacy-public-notes` vì controller hiện tại không có auth/family, không tự thay đổi mô hình bảo mật mẫu.

Hash canonical gồm body và resource ID, object key đã sắp xếp; cùng key khác body/resource → HTTP 409 `IDEMPOTENCY_KEY_REUSED`. Operation khác có namespace riêng giống cơ chế hiện hữu. Lần đầu claim `PENDING` bền vững trước side effect. Thành công lưu snapshot JSON response, kể cả `undefined` cho 204. Replay trả nguyên snapshot, không project lại entity đã bị sửa sau đó. Response status giữ nguyên decorator route. Response envelope của app vẫn hoạt động như cũ; Note vẫn raw JSON.

Snapshot generic luôn mã hóa AES-256-GCM; AAD = ledger ID. Khóa được dẫn xuất từ `AUTH_SECRET_PEPPER`, fallback `COUPLE_CHECKIN_ENCRYPTION_KEY` nếu pepper rỗng/thiếu. Không ghi nội dung journal/check-in/appreciation plaintext vào ledger. Chưa có rotation/key version: cần giữ nguồn khóa ổn định trong suốt thời gian giữ ledger. Thiếu cả hai khóa → HTTP 503 `SERVICE_UNAVAILABLE` trước claim/work.

Mỗi replay memory kiểm lại `IMemoryContentService.getById` (ACL hiện hành), rồi requireContentAccess write. Perspective replay còn bắt buộc Parent (`parentOnly`) để không lộ hidden perspective sau demote; route có family kiểm requireParent write; journal/check-in/appreciation/request kiểm thêm context Papa & Mama bằng API đọc service hiện có trước replay. Actor không đọc được ký ức hoặc mất scope không được đọc snapshot.

## JSON request/response

Các object dưới đây là payload JSON; domain route có wrapper HTTP `{"data": <payload>}`. Chuỗi `<uuid>`, `<iso>` là chỗ thay bằng giá trị thực. Không thêm/bớt field so với projection hiện tại.

- Comment request `{"body":"Nội dung","parentCommentId":null}` (`parentCommentId` tùy chọn); response `{"id":"<uuid>","memoryId":"<uuid>","authorUserId":"<uuid>","parentCommentId":null,"body":"Nội dung","createdAt":"<iso>","editedAt":null}`.
- Set reaction request `{"type":"LOVE"}` (`LOVE|CUTE|HAHA|TOUCHED|CLAP`); clear không body. Response `{"memoryId":"<uuid>","reactions":{"LOVE":1},"myReaction":"LOVE","reactionCount":1}`; clear myReaction=null, count/map theo snapshot lúc clear.
- Perspective request `{"body":"Góc nhìn","audioAssetId":null,"hiddenFromCircle":false}` (các field tùy chọn theo DTO); response `{"id":"<uuid>","memoryId":"<uuid>","authorUserId":"<uuid>","body":"Góc nhìn","audioAssetId":null,"hiddenFromCircle":false,"version":1,"createdAt":"<iso>","updatedAt":"<iso>"}`.
- Favorite/unfavorite không body; HTTP 204 không JSON.
- Note create request `{"title":"Ghi chú","content":"Nội dung"}`; patch `{"title":"Đã sửa"}` hoặc content; response raw `{"id":"<uuid>","title":"Ghi chú","content":"Nội dung","createdAt":"<iso>","updatedAt":"<iso>","deletedAt":null}`. Delete không body; 204.
- Journal create request `{"title":"Hôm nay","body":"Tâm sự","mood":"GOOD","assetIds":[]}` (title/mood/assetIds tùy chọn); response `{"id":"<uuid>","userId":"<uuid>","title":"Hôm nay","body":"Tâm sự","mood":"GOOD","assetIds":[],"createdAt":"<iso>","updatedAt":"<iso>"}`.

## Mã lỗi, concurrency và giới hạn thực tế

- UUID header sai: 400 `BAD_REQUEST` qua filter hiện có; DTO validation theo 400 `VALIDATION_ERROR`.
- Key khác body/resource: 409 `IDEMPOTENCY_KEY_REUSED`.
- Claim đang chạy hoặc kết quả không chắc chắn sau exception: 409 `IDEMPOTENCY_COMMAND_PENDING`. Client cần giữ key và retry/backoff; không tạo key mới vì có thể side effect đã commit.
- DomainError 4xx sau authorize được snapshot mã hóa và replay lại code/message/status; riêng REQUEST_RESEND_BLOCKED còn phục hồi retryAfter/subclass để filter hiện hành giữ deadline. RequestId/timestamp error envelope vẫn là metadata của HTTP attempt mới, không phải snapshot cũ.
- ACL/quota/lifecycle lỗi từ service hiện có giữ nguyên. ACL chạy trước lookup nên người mất quyền không thấy cached response.
- Các controller mới inject service với `@Optional()`: client không gửi key vẫn chạy khi chưa bổ sung binding; có key và thiếu binding → 503 `SERVICE_UNAVAILABLE`, không âm thầm chạy mất chống trùng. Riêng couple-request khi thiếu binding dùng lại native transactional ledger hiện có để bảo toàn compatibility/test cũ; native vẫn chống trùng nhưng chưa đảm bảo exact snapshot sau entity thay đổi. Muốn đầy đủ exact replay phải thêm DI dưới đây.
- **Giới hạn crash**: generic wrapper không dùng chung transaction với transaction bên trong các service cũ. Crash sau mutation/trước complete hoặc exception không xác định được giữ PENDING/FAILED và chặn side effect lần hai. Chưa có automatic reconciliation, lease, job recovery hay command quản trị để đóng claim; cần kiểm tra side effect và đối soát riêng. Không được tự xóa claim/chạy lại với key mới khi chưa rõ kết quả. Đây là chống tạo trùng fail closed, chưa phải workflow tự phục hồi hoàn chỉnh.
- Không đặt TTL/purge tự động cho generic ledger trong vòng này: tránh xóa key rồi tạo trùng offline command rất cũ; cần chính sách retention + reconciliation được triển khai riêng. Snapshot mã hóa vẫn là dữ liệu nhạy cảm, không đưa vào analytics.
