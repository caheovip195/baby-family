## HTTP contract chính xác

Prefix production `/api/v1`; mọi route sau cần Bearer access token/session còn hợp lệ qua AccessTokenGuard. Ví dụ dưới dùng UUID/thời gian minh họa, không phải dữ liệu thực. HTTP envelope `{ "data": ... }` theo interceptor hiện có.

### GET /api/v1/support/categories — 200

Không có request body:

```json
{
  "data": {
    "version": 1,
    "categories": [
      "ACCOUNT",
      "INVITATION",
      "MEDIA",
      "BILLING",
      "PRIVACY",
      "OTHER"
    ]
  }
}
```

Nguồn duy nhất: SUPPORT_HELPDESK_POLICY v1. Thêm/đổi category bằng version catalog mới trong file cấu hình này; không cần enum/migration. Ticket lưu snapshot categoryVersion, envelopeVersion; không hồi tố bản ghi cũ.

### POST /api/v1/support/tickets — 201

```json
{
  "category": "MEDIA",
  "subject": "Không thấy ảnh",
  "body": "Nội dung người gửi tự nhập",
  "familyId": "11111111-1111-4111-8111-111111111111",
  "attachmentAssetIds": ["22222222-2222-4222-8222-222222222222"]
}
```

`familyId`, `attachmentAssetIds` có thể bỏ qua. subject được trim, 1–200 ký tự; body được trim, 1–10000 ký tự. Category phân biệt hoa/thường. Tối đa 5 UUID attachment, không trùng. Chỉ `UserAsset` purpose SUPPORT, READY, chưa xóa, owner chính người gửi; không nhận family MediaAsset/ảnh của trẻ có sẵn. Tạo ticket + attachment cùng transaction; lỗi không để lại ticket dở.

```json
{
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "code": "HT-261020-33333333-3333-4333-8333-333333333333",
    "status": "OPEN",
    "createdAt": "2026-10-20T03:00:00.000Z"
  }
}
```

Code được suy ra từ ngày tạo UTC + toàn bộ UUID để không va chạm đuôi ngắn. API này không có Idempotency-Key: gửi lại request tạo ticket mới.

### GET /api/v1/me/support/tickets?offset=0&limit=50 — 200

`offset` mặc định 0, integer >=0; `limit` mặc định 50, integer 1–50. Chỉ ticket của actor chưa xóa, order createdAt DESC, id DESC.

```json
{
  "data": {
    "items": [
      {
        "id": "33333333-3333-4333-8333-333333333333",
        "code": "HT-261020-33333333-3333-4333-8333-333333333333",
        "status": "OPEN",
        "createdAt": "2026-10-20T03:00:00.000Z"

    ],
    "nextOffset": null
  }
}
```

`nextOffset` là integer offset+limit khi còn trang, ngược lại null. Offset pagination có thể dịch trang khi có ticket mới; không phải snapshot cursor.

## Mã hóa và vận hành support

Cần truyền **SUPPORT_ENCRYPTION_KEY** vào môi trường API: base64 canonical của đúng 32 byte ngẫu nhiên, lưu secret store, không đưa key vào repo/report. ConfigService đọc runtime env; chưa sửa .env.example/compose/environment.ts dùng chung. Thiếu key fail closed 503, không ghi plaintext hay fallback key của miền khác.

AES-256-GCM với IV ngẫu nhiên 12 byte; format bytea `[version=1][iv12][tag16][ciphertext]`. AAD `support:v1:ticket:<ticketId>:<requesterId>` cho JSON `{version:1,categoryVersion:1,subject,body}` trong message_enc. Tin nhắn body_enc dùng AAD `support:v1:message:<ticketId>:<messageId>`. Gắn ciphertext với đúng bản ghi, không dùng nhầm ciphertext của ticket khác. Chưa có key rotation/KMS hoặc decoder format legacy; dữ liệu cũ khác format trả 503 để không đọc sai. Cần giữ key ổn định qua lần khởi động.

Luồng upload purpose SUPPORT không thuộc yêu cầu này; attachment API nhận UserAsset SUPPORT READY đã tồn tại. Upload AVATAR/family MediaAsset không thay thế được SUPPORT. Chưa mở admin reply/tra cứu metadata CSKH, download attachment hay route đổi status.

## Moderation và job

Gom theo `(targetType,targetId)` trên case chưa xóa, chưa resolved, status OPEN/IN_REVIEW/ESCALATED. Lock report row + advisory transaction lock theo target bảo vệ báo cáo đồng thời, join upsert chống gắn trùng. Priority = min severity (1 cao nhất); SLA = min thời hạn hiện có/báo cáo mới, không kéo dài SLA khi có báo cáo mới. Case đã resolved không nhận báo cáo mới. Không hydrate nội dung target/ảnh trẻ.

Hook sau report commit best effort; failure chỉ ghi cảnh báo cố định MODERATION_ATTACH_DEFERRED, report vẫn được lưu/trả receipt. Job tìm report mở chưa gắn case active để phục hồi crash giữa hai transaction. SLA report theo Safety policy v1 (CHILD_SAFETY 24h; khác 72h), kế thừa vào case. Không thêm hành động ẩn toàn hệ thống hoặc thay logic báo cáo cũ ngoài hook.

`MODERATION_SLA_JOB`: queue maintenance, name `moderation.reconcile-sla`, maxAttempts 3, backoff 10000ms, lease 120000ms. Lịch mỗi 60000ms UTC; bỏ tick lỡ, kỳ kế tiếp quét backlog, batch tối đa 100 orphan và 100 case/kỳ. Khi backlog lớn, xử lý tiếp ở kỳ sau, không hứa xử lý hết trong một tick. Chuyển case quá SLA thành ESCALATED, không đổi report status hay gửi notification.

`runScheduled(scheduledFor, familyId?)` tạo key theo job+scope+đầu phút UTC; familyId tùy chọn chỉ để chạy scope nội bộ/test. Production scope GLOBAL. `reconcile(now, context, familyId?)` dùng JobRunner bên ngoài; không bọc JobRunner lần hai. Run/attempt/checkpoint dùng hạ tầng JobRunnerService hiện có; business writes kiểm fencing/owner/lease expiry trong transaction, retry không lặp link hoặc escalation. DB lỗi không báo success giả; report đã commit được kỳ sau phục hồi. Logs sẵn có chưa thay monitoring ngoài DB.

Lỗi service/job nội bộ: JOB_LEASE_LOST (409 DomainError khi stale fence); các lỗi DB truyền cho runner lưu failure/retry. Không có HTTP moderation route.
