## Quyết định triển khai

`media-policy.ts` đã có AVATAR nhưng `MediaService` gắn `assets.family_id`, quyền gia đình và quota. `users.avatar_asset_id` lại có FK composite tới `user_assets(id, owner_user_id)`. Vì AUTH-04 phải hoạt động trước khi có gia đình, thêm pipeline tài khoản dùng schema hiện có, tái dùng `IObjectStorageService`, MIME policy và `IImageProcessorService`; không sao chép pipeline biến thể ảnh.

Policy kỹ thuật version 1: tối đa 5 MiB, JPEG/PNG/WebP/GIF, PUT đơn; không có multipart/parts vì giới hạn nhỏ hơn ngưỡng multipart 20 MiB của media. PUT tối đa 15 phút, không vượt deadline upload 24 giờ. Complete kiểm HEAD, size, MIME, SHA-256, giải mã/re-encode và bỏ metadata, lưu thumbnail t320 WebP đồng bộ. Trạng thái `PENDING_UPLOAD → PROCESSING → READY`; retry PROCESSING/READY được hỗ trợ. Intent cùng owner + Idempotency-Key trả cùng asset, khác nội dung trả conflict; không cấp PUT mới khi PROCESSING/READY/hết hạn.

Ảnh xem nằm tại key riêng với raw, nên replay PUT không thay đổi rendition đang phục vụ. Không trả signed URL raw. URL xem TTL 1 giờ theo `MEDIA_POLICY.viewUrlTtlSeconds`; expiry là ISO 8601 trong JSON. Không có ảnh READY/variant hợp lệ hoặc storage chưa cấu hình thì field URL/expiry là null.

PATCH avatar kiểm owner, purpose AVATAR, READY, soft delete; khóa asset và cập nhật avatar cùng các trường profile khác trong một transaction. Repository sở hữu toàn bộ Prisma; service dùng Symbol interface.

## HTTP contract

Prefix thực tế `/api/v1`; tất cả route dưới đây yêu cầu Bearer authentication. Ví dụ JSON dùng dữ liệu giả; URL/thời gian/id được sinh ở runtime.

### Upload avatar

`POST /api/v1/me/avatar/upload-intents` — header `Idempotency-Key: <UUID>` bắt buộc.

```json
{
  "purpose": "AVATAR",
  "mime": "image/png",
  "size": 1234,
  "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
}
```

201:

```json
{
  "data": {
    "assetId": "11111111-1111-4111-a111-111111111111",
    "status": "PENDING_UPLOAD",
    "upload": {
      "mode": "single",
      "method": "PUT",
      "url": "<signed PUT URL>",
      "headers": {
        "Content-Type": "image/png",
        "x-amz-checksum-sha256": "<base64 checksum>"
      },
      "expiresAt": "2026-10-19T12:15:00.000Z"
    }
  }
}
```

`headers` là map do storage service trả, có thể thêm header checksum; client gửi nguyên map. Gửi bytes trực tiếp bằng PUT tới `upload.url`, không qua API. Checksum ví dụ phải thay bằng SHA-256 thực của bytes.

Replay khi PROCESSING/READY/hết deadline không có `upload`, ví dụ 201:

```json
{
  "data": {
    "assetId": "11111111-1111-4111-a111-111111111111",
    "status": "READY"
  }
}
```

`POST /api/v1/me/avatar/:id/complete`, request `{}`. Thành công 200 (đồng bộ):

```json
{
  "data": {
    "assetId": "11111111-1111-4111-a111-111111111111",
    "status": "READY"
  }
}
```

Complete chỉ owner; chưa PUT trả 409, vẫn xin lại intent cùng key được. Complete READY không xử lý ảnh lại và thử xóa mọi version raw còn lại.

### Bootstrap và Circle

Các GET không có request body. Đây là field bổ sung, giữ field cũ:

| Route                             | Vị trí field mới                                                                                                           |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `/api/v1/families/:fid/bootstrap` | `data.me`, `data.parents[]`: `avatarUrl`, `avatarUrlExpiresAt`; `data.subjects[]`: thêm cả `coverUrl`, `coverUrlExpiresAt` |
| `/api/v1/families/:fid/circle`    | `data.items[]`: `avatarUrl`, `avatarUrlExpiresAt`                                                                          |
| `/api/v1/me/circles`              | `data.items[].children[]`: 4 field ảnh, chỉ subjects đã được grant                                                         |
| `/api/v1/families/:fid/overview`  | `data.parents[]`: 2 field avatar; `data.children[]`: 4 field ảnh                                                           |

Ví dụ nguyên một phần tử `subjects[]` trong bootstrap:

```json
{
  "type": "CHILD",
  "id": "33333333-3333-4333-a333-333333333333",
  "displayName": "Synthetic child",
  "name": "Synthetic child",
  "nickname": null,
  "birthDate": "2026-01-01",
  "dueDate": null,
  "colorIndex": 0,
  "gender": null,
  "expectedCount": null,
  "seqNo": null,
  "status": "ACTIVE",
  "avatarUrl": "<signed avatar variant URL>",
  "avatarUrlExpiresAt": "2026-10-19T13:00:00.000Z",
  "coverUrl": "<signed cover variant URL>",
  "coverUrlExpiresAt": "2026-10-19T13:00:00.000Z"
}
```

Thai kỳ trả 4 field ảnh bằng null. Repository kiểm lại child thuộc family, active Parent hoặc active Circle grant/membership, đúng AVATAR/COVER purpose, asset READY và variant còn sống; không fallback raw. Circle kiểm thêm content access hiện hành. Circle bị pause/awaiting approval không có children trong `/me/circles`; revoke/không có grant không ký URL. Parent bootstrap giữ truy cập metadata khi gói chỉ đọc/hết hạn.

### Mã lỗi

| HTTP | Code                                  | Điều kiện                                                                          |
| ---- | ------------------------------------- | ---------------------------------------------------------------------------------- |
| 400  | `VALIDATION_ERROR`                    | DTO sai purpose, size ngoài 1..5242880, SHA-256 sai, avatarAssetId không phải UUID |
| 400  | `BAD_REQUEST`                         | Thiếu/sai UUID Idempotency-Key hoặc UUID path qua ParseUUIDPipe                    |
| 401  | `UNAUTHORIZED` và lỗi auth hiện có    | Thiếu/không hợp lệ Bearer/session                                                  |
| 404  | `NOT_FOUND`                           | Complete asset không có/khác owner/đã soft delete; bootstrap không thuộc family    |
| 409  | `IDEMPOTENCY_KEY_REUSED`              | Cùng key/owner nhưng khác nội dung upload                                          |
| 409  | `UPLOAD_NOT_FOUND`                    | Chưa có raw object để complete                                                     |
| 409  | `UPLOAD_EXPIRED`                      | Hết deadline hoặc không chuyển được trạng thái upload hợp lệ                       |
| 422  | `MEDIA_TYPE_UNSUPPORTED`              | MIME không thuộc IMAGE policy                                                      |
| 422  | `UPLOAD_METADATA_MISMATCH`            | HEAD size/MIME sai hoặc vượt giới hạn                                              |
| 422  | `UPLOAD_CHECKSUM_MISMATCH`            | Bytes tải về khác SHA-256/size đã khai báo                                         |
| 422  | `AVATAR_IMAGE_INVALID`                | Decoder/processor từ chối nội dung ảnh                                             |
| 422  | `AVATAR_ASSET_INVALID`                | PATCH asset không có/khác owner/khác purpose/chưa READY/đã xóa                     |
| 403  | `CIRCLE_PAUSED` và các mã ACL hiện có | Content access Circle không còn hợp lệ                                             |
| 503  | `SERVICE_UNAVAILABLE`                 | Storage/bucket/processing không cấu hình hoặc dependency báo unavailable           |

`MEDIA_TOO_LARGE` (422) là service guard khi gọi nội bộ; HTTP DTO chặn size không hợp lệ bằng 400 trước đó. Error envelope hiện có: `{"error":{"code":"...","message":"..."},"requestId":"...","path":"...","timestamp":"..."}`; `details` chỉ có khi validation trả danh sách. `requestId` có thể không xuất hiện trong focused module không cài request logger.

## Cleanup và đăng ký cần thêm

Không thêm job mới. Tái dùng `JOBS.purgeOrphans` / `media.purge-orphans`, queue maintenance, lịch hiện có mỗi 15 phút, 3 attempts, backoff 10 giây, lease 120 giây. `MediaMaintenanceService.purgeOrphans` gọi cleanup avatar và nhận JobContext từ adapter.

Giữ `purge_after` sau READY để dọn raw sau deadline PUT cộng 60 giây; xóa mọi object version, giữ rendition đang được active user tham chiếu. Pending hết hạn, PROCESSING stale 6 giờ, avatar đã bỏ/đổi và owner đã xóa được thu hồi; soft delete trước storage I/O, chỉ clear marker sau khi xóa thành công. Chỉ xử lý exact pipeline key của AVATAR này, không quét SUPPORT/legacy. Có row lock với attach, fencing khi ghi DB, signal cancellation, lịch sử run/attempt và retry từ runner hiện có. Downtime được gộp vào lần quét tiếp theo; không cần chạy lại mọi tick. Thời điểm thực dọn còn phụ thuộc batch/backlog và storage availability.
