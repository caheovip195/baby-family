## Route và JSON

```http
GET /api/v1/families/{familyId}/care-stats?weekStart=2026-10-26&childId={childUuid}
Authorization: Bearer <access-token>
```

Request không có JSON body. Hai query đều tùy chọn:

- `weekStart`: ngày thật dạng `YYYY-MM-DD`, là thứ Hai. Bỏ qua → thứ Hai của tuần hiện tại theo `family.timezone`. Khoảng cách tuyệt đối so với thứ Hai hiện tại không vượt 365 ngày (tương đương tối đa 52 tuần nguyên về mỗi phía).
- `childId`: UUID, bé còn tồn tại trong chính gia đình; bé archived/memorial vẫn xem được lịch sử. Bé deleted (theo `deletedAt` hoặc `status`) hay thuộc gia đình khác → 404.
- Field query ngoài hợp đồng (ví dụ `userId`, `owner`, `category`) bị ValidationPipe hiện có từ chối; không có lựa chọn thống kê theo người.

HTTP 200 dùng envelope chuẩn của backend. Ví dụ có 3 nhiệm vụ hợp lệ:

```json
{
  "data": {
    "weekStart": "2026-10-26",
    "weekEnd": "2026-11-01",
    "total": 3,
    "categories": [
      { "code": "CARE", "count": 2 },
      { "code": "BONDING", "count": 0 },
      { "code": "PLAY", "count": 0 },
      { "code": "OUTDOOR", "count": 0 },
      { "code": "MEMORY", "count": 0 },
      { "code": "TOGETHER", "count": 1 },
      { "code": "SUPPORT", "count": 0 },
      { "code": "SELF", "count": 0 },
      { "code": "PREP", "count": 0 },
      { "code": "HOME", "count": 0 },
      { "code": "CUSTOM", "count": 0 }
    ],
    "bloomDays": 2,
    "bloomed": [true, false, true, false, false, false, false]
  }
}
```

`weekEnd` là Chủ nhật **bao gồm**; DB truy vấn `[weekStart, thứ Hai kế tiếp)`. Category theo thứ tự catalog/enum nhiệm vụ hiện có (`MissionCategory`), đủ cả count 0, bỏ COUPLE. Không suy diễn category từ owner: nhiệm vụ TOGETHER có category CARE vẫn thuộc CARE.

Đếm một nhiệm vụ khi `status = DONE`, chưa soft delete, có completion chưa undo/chưa soft delete, cả mission/completion cùng family. Tuần dựa vào `missions.board_date`, kể cả hoàn thành muộn ở tuần kế tiếp. Loại cả `targetScope = COUPLE` và `category = COUPLE`. Quan hệ `some` và groupBy nhiệm vụ tránh nhân count bởi nhiều bé/completion. Lọc bé qua `mission_children` còn hiệu lực và child cùng family.

`bloomed` luôn 7 boolean thứ Hai → Chủ nhật, lấy ngày bảng `daily_mission_boards.board_date` có `bloomed_at`, chưa xóa; ngày chưa có bảng/hoa là false. Hoa là lịch sử gia đình, không bị thu hồi bởi undo và không thay đổi theo `childId`. `bloomDays` là số true. Không trả ID/Hearts/tên người, không ghi outbox, không push, không gửi dữ liệu cho AI/Cầu nối.

Disclaimer do app hiển thị theo yêu cầu, không thêm field ngoài response đã chốt: “Chỉ dựa trên hoạt động ghi trong app. Còn rất nhiều điều bố mẹ làm cho nhau mà app không đếm được.”

## Mã lỗi

HTTP error dùng filter chuẩn: `{ "error": { "code", "message", "details"? }, "requestId"?, "path", "timestamp" }`. Message phụ thuộc locale; details chỉ có với lỗi validation/framework.

| HTTP | `error.code`               | Điều kiện                                                                                                     |
| ---- | -------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 400  | `CARE_STATS_WEEK_INVALID`  | Sai định dạng, ngày không tồn tại, hoặc không phải thứ Hai.                                                   |
| 400  | `CARE_STATS_RANGE_INVALID` | Thứ Hai xa hơn giới hạn 365 ngày.                                                                             |
| 400  | `VALIDATION_ERROR`         | Query lạ, child UUID sai, query không phải string.                                                            |
| 400  | `BAD_REQUEST`              | `familyId` không phải UUID (ParseUUIDPipe hiện có).                                                           |
| 401  | `UNAUTHORIZED`             | Thiếu/sai token hoặc session không còn hiệu lực.                                                              |
| 402  | `SUBSCRIPTION_REQUIRED`    | Thiếu/hết entitlement hoặc effective plan không có `care.statistics === true` (bao gồm thiếu/false/sai kiểu). |
| 403  | `LICENSE_BLOCKED`          | License bị khóa hoặc access phase BLOCKED.                                                                    |
| 403  | `FAMILY_NOT_ACTIVE`        | Gia đình không ACTIVE hoặc không đủ hai Parent đang hoạt động.                                                |
| 404  | `NOT_FOUND`                | Circle/người ngoài/Parent đã rời; family không tồn tại/đã xóa; child không tồn tại/đã xóa/khác gia đình.      |

## DI cần phiên điều phối thêm

**Chưa sửa** `src/common/application/application.providers.ts`. Thêm chính xác các import sau trong file đó:

```ts
import { CareStatsController } from '../../controllers/care-stats.controller';
import { CareStatsService } from '../../services/care-stats.service';
import { CareStatsRepository } from '../../repositories/care-stats.repository';
import { CARE_STATS_SERVICE } from '../../interfaces/services/care-stats-service.interface';
import { CARE_STATS_REPOSITORY } from '../../interfaces/repositories/care-stats-repository.interface';
```

Trong `APPLICATION_CONTROLLERS` thêm:

```ts
CareStatsController,
```

Trong `APPLICATION_PROVIDERS` thêm:

```ts
{ provide: CARE_STATS_SERVICE, useClass: CareStatsService },
{ provide: CARE_STATS_REPOSITORY, useClass: CareStatsRepository },
```

`APPLICATION_ACCESS_SERVICE`, `CATALOG_QUERY_REPOSITORY`, auth guard và `PrismaService` đã được composition root cung cấp; không bind lại. Không có DI worker/job mới. Trước khi các dòng trên được tích hợp, AppModule hiện tại chưa đăng ký route này; integration spec tự dựng Nest module với đúng providers mới và providers phụ thuộc thật.
